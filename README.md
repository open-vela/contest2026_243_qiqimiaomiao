## 一、作品概述 (Product Overview)

**VocaVibe（随声记）** 是一款面向下一代端侧智能硬件的**多模态 AI 英语记忆伴侣终端**。

针对传统背单词软件枯燥、缺乏语境互动、硬件终端交互单调的痛点，VocaVibe 将**标准 Anki 记忆算法（SM-2 / FSRS 间隔预测）**、**小智声波律动视觉动效**、**Xiaomi MiMo 2.5 大语言模型**与**主动自驱提醒机制**深度融合，构建了一款触手可及的桌面级全触控 AI 硬件学习伴侣。

## 二、核心功能与设计亮点

### 1. 1:1 复刻 AnkiDroid 拟物手账多页架构 (`lv_tileview`)
基于 OpenVela LVGL 9 定制 390×450 AMOLED 全触控交互：
- **Page 0（牌组列表）**：采用经典 AnkiDroid 蓝/红/绿三色徽章计数，实时呈现各牌组新词、在学、到期待复习卡片数；支持右上角一键「同步」，从本地 AnkiConnect 流式拉取真实牌组。
- **Page 1（Anki 核心复习）**：正面大字展示单词与音标，点击翻转卡片查看释义与例句，卡片背面提供 4 档 FSRS 智能记忆间隔预测时间标签（`<1m`, `10m`, `1d`, `4d`），顶部支持一键返回牌组列表。
- **Page 2（AI 助教·灵动交互）**：暖金琥珀色呼吸灵动光球（30FPS 律动），配合小智台湾腔（晓臻音色）生动发音；支持大模型实时问答与流式打字机渲染。
- **Page 3（设置与外设代理）**：电脑宿主机网络代理连接控制、周围蓝牙音频耳机自动扫描与一键配对。

### 2. 主动任务（Proactive Task）与端侧自驱提醒
突破传统背词硬件只能“被动等待用户点击”的局限，VocaVibe 实现了**端侧主动自驱服务**：
- **后台守护进程**：独立线程周期巡检 `/data/vocavibe/deck.json`，检测今日到期待复习卡片。
- **视觉自驱切色**：触发自驱提醒时，AI 助教呼吸光球自适应从暖金色切换为**柔和翠绿律动**（`0x2E7D32`）。
- **多模态主动唤醒**：屏幕自动弹出「⏰ 学习自驱提醒」弹窗并调度语音播报：“主人，你今天还有 X 张单词卡片待复习，赶紧开始吧！”，用户轻触「立即复习」即可直达复习界面。

### 3. 规范沉淀的两大 AI Skills
本项目严格遵循大赛 AI-Native 规范，在 `skills/` 目录下沉淀了 2 个高价值端侧 AI Skill：
- [`skills/anki-card-manager.md`](skills/anki-card-manager.md)：卡组与卡片端侧管理技能，支持通过自然语言对 Anki 卡片执行增、删、改、查与进度同步。
- [`skills/proactive-review-reminder.md`](skills/proactive-review-reminder.md)：自驱复习主动提醒技能，定义了后台低功耗巡检、翠绿光球变色预警与主动语音播报的完整调度规范。

## 三、⚠️ 诚实说明：已知问题与未完全实现部分 (Known Limitations)

> **致各位评审老师**：因备赛时间紧迫与端侧硬件资源限制，本项目仍存在若干未彻底攻克的技术难点与缺陷，在此如实汇报，绝不隐瞒：

1. **部分音标存在方块乱码问题**：
   - **现状**：虽然我们烘焙了 GB2312 常用汉字与标准国际音标（IPA）字库，但英语音标库中存在大量重音上标、长音符号（`ː`）、希腊变体字符及特殊重音变音符。受限于 SF32LB52 片上 Flash 空间与点阵字库覆盖率，在部分特定词条的音标展示中仍偶现 `□` 豆腐块乱码。

2. **HTML 富文本格式无法在嵌入式屏幕原生渲染**：
   - **现状**：桌面端 Anki 词库大量使用复杂的 HTML 标签、CSS 样式表（如柯林斯词典的多色标签、折叠面板、发音音标控件等）。由于嵌入式 LVGL 仅原生支持极简文本标签，无法像完整 Web 浏览器一样排版 CSS。当前网关端只能强行剥离 HTML 标签降级为纯文本，导致排版格式缺失或内容紧缩。

3. **ASR 语音识别与英文专有名词误识别**：
   - **现状**：本地轻量级 Whisper 模型在麦克风远场环境下对英文专有名词（例如比赛指定唤醒词 `openvela`）识别率偏低，极易误识别为拼音近音词（如“你好不回来”等中文谐音）。需要较为严格的发音和相对安静的声学环境，鲁棒性仍显不足。

4. **端云半双工对话流畅度与时延较大**：
   - **现状**：整个语音交互链路（麦克风采集 $\to$ 本地 VAD 判决 $\to$ Whisper ASR $\to$ 串口 UART 传输 $\to$ MiMo 2.5 云端推理 $\to$ TTS 音频合成 $\to$ 音频回放）涉及较多转接节点。由于串口波特率与半双工并发控制机制，整套对话的往返延迟较为明显，缺乏打断能力，对话体验尚未达到消费级智能音箱的丝滑程度。

5. **总结**：
   - 受限于比赛截止时间，上述系统级多模态通信与富文本排版瓶颈未能在此版本中彻底完善，团队已将其作为赛后持续攻关与迭代优化的核心路线。

## 四、快速构建与固件烧录

### 1. 编译板端固件
在 openvela 根目录下执行：
```bash
ninja -C cmake_out/sf32lb52_devkit_lcd nuttx.bin
```

### 2. 烧录固件至板端 Flash
使用 `sftool` 写入板端（波特率 1,000,000）：
```bash
sftool -c SF32LB52 -p /dev/ttyACM0 -b 1000000 \
       --before default_reset --after soft_reset \
       write_flash cmake_out/sf32lb52_devkit_lcd/nuttx.bin@0x12010000
```

### 3. 运行 PC 伴侣端网关 (Companion)
打通 MiMo 2.5 大模型、蓝牙代理与 AnkiConnect：
```bash
python3 tools/companion_pc.py /dev/ttyACM0
```
